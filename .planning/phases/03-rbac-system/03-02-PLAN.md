1. Import statements:
   - from typing import List, Optional

   - from src.rbac.models import Role, Permission, RolePermission, UserRole
   - from src.auth.models import User

2. Implement async def get_user_role(user_sub: str, tenant_id: str, session: Session) -> Optional[Role]:
   - Query: session.query(UserRole).filter(UserRole.user_sub == user_sub, UserRole.tenant_id == tenant_id).join(Role).first()
   - Return Role object if found, None if user has no role in this tenant
   - Log: "No role found for user {user_sub} in tenant {tenant_id}" if None

3. Implement async def get_role_permissions(role_id: str, session: Session) -> List[Permission]:
   - Query: session.query(Permission).join(RolePermission).filter(RolePermission.role_id == role_id).all()
   - Return list of Permission objects
   - Handle empty list (role exists but has no permissions)

4. Implement async def get_user_permissions(user: User, tenant_id: str, session: Session) -> List[str]:
   - Get user's role in tenant: role = await get_user_role(user.sub, tenant_id, session)
   - If no role: return []
   - Get permissions: perms = await get_role_permissions(role.id, session)
   - Return permission names as list: [f"{p.resource}:{p.action}" for p in perms]
   - Example return: ["findings:read", "findings:write", "scans:execute"]

5. Implement def has_permission(user_permissions: List[str], required_permission: str) -> bool:
   - Check wildcard first: if "*:*" in user_permissions: return True
   - Check exact match: if required_permission in user_permissions: return True
   - Check resource wildcard: if required_permission.split(":")[0] + ":*" in user_permissions: return True
   - Return False if no match
   - Example: has_permission(["findings:*"], "findings:read") → True
   - Example: has_permission(["findings:read"], "findings:write") → False

6. Implement def has_role_level(user_role_level: int, required_level: int) -> bool:
   - Role hierarchy: Lower level number = higher privilege (1=Super Admin, 5=User)
   - Return user_role_level <= required_level
   - Example: has_role_level(2, 3) → True (Admin level=2 can access Analyst level=3 resource)
   - Example: has_role_level(4, 3) → False (Manager level=4 cannot access Analyst level=3 resource)

WHY these patterns:
- Separate functions enable testing and reuse
- Wildcard matching prevents permission explosion (*:* is 1 permission, not 100+)
- Role level comparison enables hierarchical access (Admin inherits Analyst permissions)
- Returning [] for users without roles prevents false positives
- CRITICAL: Always filter by tenant_id to prevent cross-tenant access

DO NOT:
- Cache at this layer (caching happens in Task 3 via Redis)
- Allow missing tenant_id (MUST be provided, no default to current_org)
- Skip wildcard checking (super admin needs *:* support)
- Use >= for level comparison (lower number = higher privilege)

1. Import statements:

   - import logging; logger = logging.getLogger(__name__)

2. Implement def get_tenant_id_from_request(request: Request) -> str:
   - Extract tenant from request.state.organization_id (set by OrganizationContextMiddleware)
   - If not present, raise HTTPException(400, "Tenant context required")
   - Return tenant_id as string
   - WHY: Tenant context must be explicit, never default to avoid security holes

3. Implement def require_permissions(*required_perms: str) -> Callable:
   - Return a FastAPI dependency function that checks permissions
   - Signature: async def permission_checker(user: User = Depends(get_current_user), tenant_id: str = Depends(get_tenant_id_from_request), session: Session = Depends(get_db)) -> User:
   - Get user permissions: user_perms = await get_user_permissions(user, tenant_id, session)
   - Check each required permission: for perm in required_perms: if not has_permission(user_perms, perm): raise HTTPException(403, f"Permission denied: {perm}")
   - If all checks pass, return user (enables chaining)
   - Log authorization failure: logger.warning(f"Permission denied for {user.email}: required {perm}, has {user_perms}")
   - WHY: Dependency pattern makes routes self-documenting, fails before handler runs

4. Implement def require_role(min_role_level: int) -> Callable:
   - Return a FastAPI dependency function that checks role level
   - Signature: async def role_checker(user: User = Depends(get_current_user), tenant_id: str = Depends(get_tenant_id_from_request), session: Session = Depends(get_db)) -> User:
   - Get user role: role = await get_user_role(user.sub, tenant_id, session)
   - If no role: raise HTTPException(403, "No role assigned in this tenant")
   - Check level: if not has_role_level(role.level, min_role_level): raise HTTPException(403, f"Role level insufficient: required {min_role_level}, has {role.level}")
   - Return user if check passes
   - Log failure: logger.warning(f"Role check failed for {user.email}: required level {min_role_level}, has {role.level}")

5. Implement async def require_tenant_access(resource_id: str, resource_type: str, user: User, session: Session) -> None:
   - Helper function to verify resource belongs to user's tenant
   - Query resource by ID and check resource.organization_id matches user's tenant
   - If mismatch: raise HTTPException(404, "Resource not found") (404, not 403, to prevent information disclosure)
   - Used inside route handlers for resource-level checks
   - Example: await require_tenant_access(finding_id, "finding", user, session)

6. Update src/rbac/__init__.py to export require_permissions, require_role, require_tenant_access

Usage examples (document in docstrings):
```python
# Permission-based protection
@router.get("/findings", dependencies=[Depends(require_permissions("findings:read"))])
async def list_findings(user: User = Depends(get_current_user)):
    return {"findings": [...]}

# Role-based protection (level 3 = Analyst and above)
@router.post("/scans", dependencies=[Depends(require_role(3))])
async def create_scan(user: User = Depends(get_current_user)):
    return {"scan_id": "..."}

# Resource-level tenant check (inside handler)
@router.get("/findings/{finding_id}", dependencies=[Depends(require_permissions("findings:read"))])
async def get_finding(finding_id: str, user: User = Depends(get_current_user), session: Session = Depends(get_db)):
    await require_tenant_access(finding_id, "finding", user, session)
    return await session.get_finding(finding_id)
```

WHY these patterns:
- Dependencies run BEFORE route handler (authorization before data access prevents timing attacks)
- Returning user enables dependency chaining and access to user info in handler
- 404 instead of 403 for tenant violations prevents tenant enumeration
- Separate require_tenant_access for resource-level checks (can't be done in dependency)

DO NOT:
- Allow authorization checks inside route handlers before dependency (defeats purpose)
- Return 403 for missing resources (use 404 to prevent information disclosure)
- Skip tenant_id validation (missing tenant = security hole)
- Cache user_perms here (caching happens in Task 3)

   - Subscribe to "permission_invalidation" channel
   - Message format: {"user_sub": "...", "tenant_id": "..."}

   - Start listener in background task (FastAPI lifespan event)

   - Check cache first: cached = await get_cached_permissions(user.sub, tenant_id)

WHY caching is critical:
- RESEARCH.md Pitfall #6: Fetching permissions on every request adds >100ms latency
- 5-minute TTL balances performance vs staleness (role changes rare, latency critical)
- Pub/sub invalidation enables immediate cache clearing when roles change
- Per-user-per-tenant keys enable granular invalidation
- LRU eviction policy prevents memory exhaustion

DO NOT:
- Use infinite TTL (permissions must refresh after role changes)
- Cache at HTTP layer (cache needs to be invalidated by DB writes)
- Skip error handling (Redis unavailable should not break auth)
- Cache *:* wildcard indefinitely (still use TTL for consistency)
