  <action>
Create new file src/rbac/models.py with SQLAlchemy models:

1. Import statements:
   - from sqlalchemy import Column, String, Integer, ForeignKey, DateTime, Boolean, UniqueConstraint
   - from sqlalchemy.dialects.postgresql import UUID
   - from sqlalchemy.orm import relationship
   - from sqlalchemy.sql import func, text
   - from src.api.database import Base

2. Role model:
   - __tablename__ = "roles"
   - id: UUID(as_uuid=True), primary_key=True, server_default=text("gen_random_uuid()")
   - name: String(50), unique=True, nullable=False (e.g., "super_admin", "admin", "analyst")
   - display_name: String(100), nullable=False (e.g., "Super Administrator")
   - description: String(255) (e.g., "Full system access across all tenants")
   - level: Integer, nullable=False (1=Super Admin, 2=Admin, 3=Analyst, 4=Manager, 5=User)
   - created_at: DateTime, server_default=func.now()
   - Relationships: permissions via RolePermission, users via UserRole

3. Permission model:
   - __tablename__ = "permissions"
   - id: UUID(as_uuid=True), primary_key=True, server_default=text("gen_random_uuid()")
   - name: String(100), unique=True, nullable=False (e.g., "findings:read", "scans:execute")
   - resource: String(50), nullable=False (e.g., "findings", "scans", "*")
   - action: String(50), nullable=False (e.g., "read", "write", "execute", "*")
   - description: String(255)
   - created_at: DateTime, server_default=func.now()
   - UniqueConstraint("resource", "action", name="uq_permission_resource_action")
   - Relationships: roles via RolePermission

4. RolePermission model (join table):
   - __tablename__ = "role_permissions"
   - id: UUID(as_uuid=True), primary_key=True, server_default=text("gen_random_uuid()")
   - role_id: UUID(as_uuid=True), ForeignKey("roles.id", ondelete="CASCADE"), nullable=False
   - permission_id: UUID(as_uuid=True), ForeignKey("permissions.id", ondelete="CASCADE"), nullable=False
   - created_at: DateTime, server_default=func.now()
   - UniqueConstraint("role_id", "permission_id", name="uq_role_permission")
   - Relationships: role, permission

5. UserRole model (CRITICAL: tenant-scoped):
   - __tablename__ = "user_roles"
   - id: UUID(as_uuid=True), primary_key=True, server_default=text("gen_random_uuid()")
   - user_sub: String(255), nullable=False (from OIDC sub claim - matches User.sub)
   - tenant_id: UUID(as_uuid=True), ForeignKey("organizations.id", ondelete="CASCADE"), nullable=False
   - role_id: UUID(as_uuid=True), ForeignKey("roles.id", ondelete="CASCADE"), nullable=False
   - created_at: DateTime, server_default=func.now()
   - updated_at: DateTime, server_default=func.now(), onupdate=func.now()
   - UniqueConstraint("user_sub", "tenant_id", name="uq_user_tenant_role") (one role per user per tenant)
   - Relationships: role, organization (tenant)

6. Create src/rbac/__init__.py that exports all models

WHY these design choices:
- level field enables hierarchy comparisons (Admin level=2 can access Manager level=4 resources)
- tenant_id in UserRole is CRITICAL - roles are scoped per tenant (admin in Tenant A ≠ admin in Tenant B)
- user_sub instead of user_id because User model is Pydantic (not ORM) - matches against JWT sub claim
- UniqueConstraint on user_sub+tenant_id prevents duplicate role assignments
- resource:action separation enables flexible permission querying
- Wildcard support (*:* for super admin) via string matching

DO NOT:
- Create a User ORM model (User is Pydantic from Phase 2, represents JWT claims)
- Add organization_id to Role or Permission (roles/perms are global definitions, only UserRole is tenant-scoped)
- Use Integer IDs instead of UUIDs (breaks existing pattern)
- Hardcode permissions in code (all permissions live in database)
