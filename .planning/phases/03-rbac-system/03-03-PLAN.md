Create src/rbac/audit.py with structured audit event logging:

1. Import statements:
   - from typing import Optional, Dict, Any, List
   - from datetime import datetime
   - from loguru import logger
   - from src.auth.models import User
   - import json

2. Define audit event types (constants):
   - AUTHORIZATION_GRANTED = "authorization.granted"
   - AUTHORIZATION_DENIED = "authorization.denied"
   - DATA_ACCESS = "data.access"
   - DATA_MODIFICATION = "data.modification"
   - ADMIN_ACTION = "admin.action"
   - ROLE_ASSIGNMENT = "role.assignment"

3. Implement def audit_authorization(
       user: User,
       tenant_id: str,
       resource: str,
       action: str,
       granted: bool,
       reason: Optional[str] = None,
       required_permissions: Optional[List[str]] = None,
       user_permissions: Optional[List[str]] = None
   ) -> None:
   - Event type: AUTHORIZATION_GRANTED if granted else AUTHORIZATION_DENIED
   - Log structured event:
     ```python
     event = {
         "event_type": AUTHORIZATION_GRANTED if granted else AUTHORIZATION_DENIED,
         "timestamp": datetime.utcnow().isoformat(),
         "user": {
             "sub": user.sub,
             "email": user.email,
             "provider": user.provider
         },
         "tenant_id": tenant_id,
         "resource": resource,
         "action": action,
         "granted": granted,
         "reason": reason,
         "required_permissions": required_permissions,
         "user_permissions": user_permissions
     }
     ```
   - Use logger.info() for granted, logger.warning() for denied
   - Log message: f"Authorization {'granted' if granted else 'DENIED'} for {user.email}: {action} on {resource}"

4. Implement def audit_data_access(
       user: User,
       tenant_id: str,
       resource_type: str,
       resource_id: Optional[str],
       action: str,
       metadata: Optional[Dict[str, Any]] = None
   ) -> None:
   - Event type: DATA_ACCESS
   - Log structured event:
     ```python
     event = {
         "event_type": DATA_ACCESS,
         "timestamp": datetime.utcnow().isoformat(),
         "user": {
             "sub": user.sub,
             "email": user.email
         },
         "tenant_id": tenant_id,
         "resource": {
             "type": resource_type,
             "id": resource_id,
             "action": action
         },
         "metadata": metadata
     }
     ```
   - Use logger.info()
   - Log message: f"Data access by {user.email}: {action} {resource_type}/{resource_id or 'list'}"
   - Examples: audit_data_access(user, tenant_id, "finding", finding_id, "read")

5. Implement def audit_data_modification(
       user: User,
       tenant_id: str,
       resource_type: str,
       resource_id: str,
       action: str,
       changes: Optional[Dict[str, Any]] = None
   ) -> None:
   - Event type: DATA_MODIFICATION
   - Log structured event (similar to data_access but includes changes dict)
   - Use logger.info()
   - Examples: audit_data_modification(user, tenant_id, "finding", finding_id, "update", {"status": "resolved"})

6. Implement def audit_admin_action(
       user: User,
       tenant_id: str,
       action: str,
       target: Optional[str] = None,
       details: Optional[Dict[str, Any]] = None
   ) -> None:
   - Event type: ADMIN_ACTION
   - Log structured event for privileged operations
   - Use logger.warning() (higher visibility for admin actions)
   - Log message: f"ADMIN ACTION by {user.email}: {action}"
   - Examples: audit_admin_action(user, tenant_id, "assign_role", target="user@example.com", details={"role": "admin"})

7. Implement def audit_role_assignment(
       admin_user: User,
       tenant_id: str,
       target_user_sub: str,
       role_name: str,
       action: str  # "assigned" or "revoked"
   ) -> None:
   - Event type: ROLE_ASSIGNMENT
   - Log structured event for role changes
   - Use logger.warning() (security-sensitive operation)
   - Log message: f"Role {action} by {admin_user.email}: {role_name} for user {target_user_sub}"

WHY structured logging:
- JSON format enables parsing by SIEM tools (Cribl, Splunk, ELK)
- Consistent event schema enables automated alerting
- Timestamp + user + tenant + resource = complete audit trail
- Separate event types enable targeted monitoring
- CRITICAL: Log BOTH success AND failure (failures indicate attacks)

DO NOT:
- Log sensitive data (passwords, tokens, PII) in events
- Skip logging authorization failures (critical for security monitoring)
- Use print() or generic logger.debug() (structured events required)
- Store audit logs in application database (use Loguru → Cribl)
