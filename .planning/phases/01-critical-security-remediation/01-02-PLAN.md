# Plan 01-02: Rotate Exposed Credentials

**Phase:** 1 - Critical Security Remediation
**Status:** Not started
**Created:** 2026-01-12

## Goal

Rotate all exposed credentials found in `.env` file and establish proper secrets management to prevent future credential exposure.

## Context

Critical security exposure identified in [CONCERNS.md:75-83](../.planning/codebase/CONCERNS.md#L75-L83):
- Real API keys and tokens are hardcoded in `.env` file
- Includes GitHub token, Azure AI Foundry key, Jira token, and other sensitive credentials
- While `.gitignore` excludes `.env`, the file exists in repository and may have been committed previously
- For security platform, credential exposure is unacceptable risk

## Tasks

### Task 1: Audit exposed credentials

**File:** [.env](.env)

**Actions:**
1. Read [.env](.env) file to inventory all credentials
2. Document each credential type and where it's used in codebase:
   - GitHub personal access token (PAT)
   - Azure AI Foundry API key
   - Jira API token
   - Any other API keys, tokens, or passwords
3. Grep codebase for usage locations of each credential variable
4. Create rotation checklist with priority order (high-risk services first)

**Expected output:**
- Markdown document listing each credential, its purpose, and usage locations
- Priority order for rotation based on exposure risk

### Task 2: Rotate GitHub credentials

**Services affected:** GitHub API access for repository scanning

**Actions:**
1. Log into GitHub as the service account or user whose PAT is exposed
2. Navigate to Settings → Developer settings → Personal access tokens
3. Revoke the exposed token immediately
4. Generate new PAT with minimal required scopes:
   - `repo` (if accessing private repos)
   - `read:org` (if scanning organization repos)
   - `read:user` (for user context)
5. Update local `.env` file with new token
6. Verify scanning functionality works with new token
7. Document token scope and rotation date

**Success check:**
- Old token returns 401 Unauthorized when used
- New token successfully authenticates API calls
- Repository scanning works end-to-end

### Task 3: Rotate Azure AI credentials

**Services affected:** Azure AI Foundry / OpenAI API integration

**Actions:**
1. Log into Azure Portal
2. Navigate to Azure AI Foundry resource
3. Regenerate API key (primary or secondary key)
4. Update [.env](.env) with new key
5. Test AI provider functionality:
   - Run [test_ai_providers.py](test_ai_providers.py) if available
   - Verify remediation generation works
6. Document key rotation date

**Success check:**
- Old key fails authentication
- New key successfully calls Azure AI APIs
- AI-powered remediation features functional

### Task 4: Rotate Jira credentials

**Services affected:** Jira integration for issue tracking

**Actions:**
1. Log into Jira account
2. Navigate to Account settings → Security → API tokens
3. Revoke exposed token
4. Generate new API token
5. Update [.env](.env) with new token
6. Test Jira integration:
   - Create test issue via API
   - Verify issue creation from findings
7. Document token rotation date

**Success check:**
- Old token fails authentication
- New token successfully creates Jira issues
- Integration features work end-to-end

### Task 5: Implement .env.example template

**File:** Create [.env.example](.env.example)

**Actions:**
1. Copy [.env](.env) structure to new `.env.example` file
2. Replace all actual credential values with placeholder format:
   ```
   GITHUB_TOKEN=ghp_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
   AZURE_AI_KEY=XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
   JIRA_API_TOKEN=XXXXXXXXXXXXXXXXXXXXXXXXXXXX
   ```
3. Add comments documenting each variable's purpose and where to obtain it
4. Add `.env.example` to git tracking (safe, no real credentials)
5. Update `.gitignore` to ensure `.env` remains excluded

**Expected output:**
- [.env.example](.env.example) file with placeholder credentials and documentation
- Developers can copy `.env.example` to `.env` and fill in real values

- [ ] Azure AI API key rotated, old key revoked, new key tested
- [ ] Jira API token rotated, old token revoked, new token tested

## Risk Assessment

**Risk level:** CRITICAL
**Impact:** Exposed credentials allow unauthorized access to GitHub repos, AI services, and Jira
**Effort:** Low-Medium (manual rotation across 3-4 services, testing required)
**Dependencies:** Access to service accounts on GitHub, Azure, Jira

## Notes

- **URGENT:** Rotate credentials immediately to minimize exposure window
- Check git history: If `.env` was ever committed, credentials are permanently exposed in git history
  - Use `git log --all --full-history -- .env` to check
  - If found, consider all credentials compromised and rotate immediately
  - Use BFG Repo-Cleaner or `git filter-branch` to remove from history if needed
- Future enhancement (Phase 2+): Migrate to proper secrets manager (AWS Secrets Manager, HashiCorp Vault)
- For development: Document credential acquisition process in README or CONTRIBUTING guide
- Consider implementing pre-commit hook to detect secrets (e.g., gitleaks, detect-secrets)
