**Phase:** 1 - Critical Security Remediation
**Status:** Not started

- 50+ bare `except: pass` blocks silently swallow all exceptions
- Errors appear successful when they actually failed
- Debugging is extremely difficult without error visibility

## Notes

- **Pattern to avoid:** Never use bare `except:` or `except Exception:` without specific justification
- **Logging best practice:** Always log the exception with context (operation, inputs, state)
- **Error handling strategy:**
  - **Critical operations:** Log and re-raise exception (let caller handle)
  - **Best-effort operations:** Log and continue with fallback (e.g., empty results)
  - **Cleanup operations:** Log warning but don't propagate (cleanup is best-effort)
- **Testing:** Introduce error conditions to verify logging and error handling work correctly
- Use Loguru's `logger.exception()` to automatically include stack trace in error logs
- Consider adding custom exception types for domain-specific errors (e.g., `ScannerParsingError`, `AIProviderError`)
