# Plan 01-01: Fix SQL Injection Vulnerabilities

**Phase:** 1 - Critical Security Remediation
**Status:** Not started
**Created:** 2026-01-12

## Goal

Eliminate SQL injection vulnerabilities by replacing f-string SQL construction with parameterized queries using SQLAlchemy bindparams or psycopg2 parameters.

## Context

Three critical SQL injection points identified:
- [src/api/database_router.py:153](src/api/database_router.py#L153) - Database existence check with f-string
- [src/api/database_router.py:159](src/api/database_router.py#L159) - Database creation with f-string
- [execution/init_db.py:51](execution/init_db.py#L51) - Database check in initialization script

All use `tenant.database_name` or `target_db` variables directly in SQL without validation or parameterization, allowing injection of malicious SQL commands.

## Tasks

### Task 1: Fix database_router.py SQL injection (database check)

**File:** [src/api/database_router.py:153](src/api/database_router.py#L153)

**Current vulnerable code:**
```python
text(f"SELECT 1 FROM pg_database WHERE datname = '{tenant.database_name}'")
```

**Actions:**
1. Read [src/api/database_router.py](src/api/database_router.py) to understand context
2. Replace f-string with SQLAlchemy `bindparam()` for safe parameterization
3. Add input validation: database name must match `^[a-z0-9_]+$` regex before query
4. Test with valid and edge-case database names

**Expected result:**
```python
from sqlalchemy import text, bindparam

# Validate database name format
if not re.match(r'^[a-z0-9_]+$', tenant.database_name):
    raise ValueError(f"Invalid database name format: {tenant.database_name}")

# Use parameterized query
text("SELECT 1 FROM pg_database WHERE datname = :db_name").bindparams(db_name=tenant.database_name)
```

### Task 2: Fix database_router.py SQL injection (database creation)

**File:** [src/api/database_router.py:159](src/api/database_router.py#L159)

**Current vulnerable code:**
```python
text(f'CREATE DATABASE "{tenant.database_name}"')
```

**Actions:**
1. Read surrounding context in [src/api/database_router.py](src/api/database_router.py) around line 159
2. Use SQL identifier escaping via `psycopg2.extensions.quote_ident()` or validated identifiers
3. Ensure database name validation from Task 1 is applied before this operation
4. Add error handling for database creation failures

**Expected result:**
```python
from psycopg2 import sql

# Validation already done in Task 1
# Use psycopg2.sql.Identifier for safe database name escaping
query = sql.SQL("CREATE DATABASE {}").format(sql.Identifier(tenant.database_name))
```

### Task 3: Fix init_db.py SQL injection

**File:** [execution/init_db.py:51](execution/init_db.py#L51)

**Current vulnerable code:**
```python
cur.execute(f"SELECT 1 FROM pg_database WHERE datname = '{target_db}'")
```

**Actions:**
1. Read [execution/init_db.py](execution/init_db.py) to understand usage context
2. Replace f-string with psycopg2 parameterized query using `%s` placeholder
3. Add same input validation as Task 1 for `target_db` variable
4. Verify this script's usage in deployment/initialization workflows

**Expected result:**
```python
# Validate database name
if not re.match(r'^[a-z0-9_]+$', target_db):
    raise ValueError(f"Invalid database name format: {target_db}")

# Use parameterized query
cur.execute("SELECT 1 FROM pg_database WHERE datname = %s", (target_db,))
```

## Success Criteria

- [ ] All three SQL injection points fixed with parameterized queries
- [ ] Database name validation regex applied before all database operations
- [ ] No f-strings or string concatenation used in SQL commands involving user/tenant input
- [ ] Code tested with normal database names (e.g., `org_acme`, `tenant_123`)
- [ ] Code tested with injection attempts (e.g., `'; DROP DATABASE postgres; --`)
- [ ] Validation properly rejects malicious input before reaching database

## Risk Assessment

**Risk level:** CRITICAL
**Impact:** SQL injection allows complete database compromise, data exfiltration, or destruction
**Effort:** Low (3 file locations, straightforward parameterization)
**Dependencies:** None

## Notes

- PostgreSQL parameterized queries use `:param` syntax with SQLAlchemy or `%s` with psycopg2
- Database identifiers (table/database names) cannot be parameterized in PostgreSQL, must use `psycopg2.sql.Identifier()`
- Validation regex `^[a-z0-9_]+$` prevents special characters that could enable SQL injection
- Consider adding database name sanitization utility function if pattern repeats elsewhere
