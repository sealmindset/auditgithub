  <action>
1. In src/auth/models.py:
   - Import: from pydantic import BaseModel
   - Create class User(BaseModel):
     * email: str
     * name: str
     * sub: str  # Subject claim (unique user ID)
     * provider: str  # "entra" or "okta"
2. In src/auth/middleware.py:
   - Import: from fastapi import HTTPException, status
   - Import: from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials
   - Import: from jose import jwt, JWTError
   - Import: from cachetools import TTLCache
   - Import: import httpx
   - Import: from src.auth.config import settings
   - Import: import logging; logger = logging.getLogger(__name__)
   - Create: security = HTTPBearer(auto_error=False)
   - Create: jwks_cache = TTLCache(maxsize=10, ttl=86400)  # 24-hour cache
   - Implement async def get_jwks(discovery_url: str) -> dict:
     * Check if discovery_url in jwks_cache, return cached if exists
     * async with httpx.AsyncClient() as client:
       - discovery = await client.get(discovery_url); discovery.raise_for_status()
       - jwks_uri = discovery.json()["jwks_uri"]
       - jwks_response = await client.get(jwks_uri); jwks_response.raise_for_status()
       - jwks_data = jwks_response.json()
       - jwks_cache[discovery_url] = jwks_data
       - return jwks_data
   - Implement async def validate_jwt_token(token: str, provider: str) -> dict:
     * Determine discovery_url based on provider (entra or okta)
     * Get jwks = await get_jwks(discovery_url)
     * unverified_header = jwt.get_unverified_header(token)
     * kid = unverified_header.get("kid")
     * Find key in jwks["keys"] matching kid, raise HTTPException(401, "Invalid token: key not found") if not found
     * claims = jwt.decode(token, key, algorithms=["RS256", "RS384", "RS512"], audience=settings.entra_client_id if provider == "entra" else settings.okta_client_id, options={"verify_aud": True, "verify_iss": True, "verify_exp": True})
     * return claims

Why: Cache JWKS with 24-hour TTL to prevent performance issues - fetching on every request adds >100ms latency (see RESEARCH.md "Common Pitfalls #6"). Explicit algorithm whitelist ["RS256", "RS384", "RS512"] prevents "none" algorithm attack (see RESEARCH.md "Common Pitfalls #2"). Validate aud/iss/exp claims to prevent confused deputy attacks (see RESEARCH.md "Common Pitfalls #1"). DO NOT allow "none" algorithm - enables trivial token forgery. DO NOT skip claim validation - tokens from other apps could be accepted. DO NOT use HS256 if expecting RS256 - another attack vector.

  <action>
In src/auth/dependencies.py:
1. Import: from fastapi import Depends, HTTPException, Request, status
2. Import: from fastapi.security import HTTPAuthorizationCredentials
3. Import: from src.auth.models import User
4. Import: from src.auth.middleware import security, validate_jwt_token
5. Import: from jose import JWTError
6. Implement async def get_current_user_from_session(request: Request) -> User:
   - Get user_data = request.session.get('user')
   - If not user_data: raise HTTPException(status_code=status.HTTP_401_UNAUTHORIZED, detail="Not authenticated", headers={"WWW-Authenticate": "Bearer"})
   - Return User(**user_data)
7. Implement async def get_current_user_from_token(credentials: HTTPAuthorizationCredentials = Depends(security)) -> User:
   - If not credentials: raise HTTPException(401, "Not authenticated", headers={"WWW-Authenticate": "Bearer"})
   - token = credentials.credentials
   - Try:
     * For each provider in ["entra", "okta"]:
       - Try: claims = await validate_jwt_token(token, provider)
       - If successful: return User(email=claims['email'], name=claims.get('name', ''), sub=claims['sub'], provider=provider)
       - Except JWTError: continue
     * If no provider validates: raise HTTPException(401, "Invalid token")
   - Except Exception as e:
     * Raise HTTPException(401, f"Token validation failed: {str(e)}")
8. Create convenience alias: get_current_user = get_current_user_from_session  # Default to session-based auth

Why: Provide both session-based and token-based auth dependencies for flexibility. Session-based (cookies) is simpler for browser apps, token-based (Bearer) is standard for API clients. Try both providers in token validation since we can't know which IdP issued the token without parsing claims first. WWW-Authenticate header is required by RFC 6750 for 401 responses. DO NOT hardcode single provider - multi-provider support is a requirement. DO NOT expose token validation errors in detail field - leaks security info to attackers.
