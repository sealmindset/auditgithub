   - Import: from fastapi import APIRouter, Request, HTTPException
   - Import: from starlette.responses import RedirectResponse
   - Import: from src.auth.providers import oauth
   - Create: router = APIRouter(prefix="/auth", tags=["authentication"])
   - Implement @router.get("/login/{provider}") async def login(provider: str, request: Request):
     * Validate provider in ["entra", "okta"], raise HTTPException(400) if not
     * Get redirect_uri = str(request.url_for('callback', provider=provider))
     * Return await oauth[provider].authorize_redirect(request, redirect_uri, code_challenge_method='S256')
2. In src/api/main.py (after line 100, with other router includes):
   - Import: from .routers import auth
   - Add: app.include_router(auth.router)

Why: PKCE (Proof Key for Code Exchange) prevents authorization code interception attacks. Force code_challenge_method='S256' even though Authlib enables PKCE automatically - explicit is better than implicit for security-critical code (see RESEARCH.md "Common Pitfalls #4"). DO NOT use 'plain' code_challenge_method - S256 (SHA-256) is required. DO NOT allow wildcard providers - validate against whitelist to prevent SSRF attacks.

<task type="auto">
  <name>Task 2: Create /auth/callback/{provider} endpoint with token exchange and session storage</name>
  <files>src/api/routers/auth.py</files>
  <action>
In src/api/routers/auth.py, implement @router.get("/callback/{provider}", name="callback") async def callback(provider: str, request: Request):
1. Validate provider in ["entra", "okta"], raise HTTPException(400) if not
2. Wrap in try/except block catching Exception:
   - Try:
     * token = await oauth[provider].authorize_access_token(request)
     * user_info = token.get('userinfo')
     * If not user_info: user_info = oauth[provider].parse_id_token(token, nonce=request.session.get('nonce'))
     * Validate email_verified claim: if user_info.get('email') and not user_info.get('email_verified'): raise HTTPException(400, "Email not verified")
     * Store session: request.session['user'] = {'provider': provider, 'email': user_info['email'], 'name': user_info.get('name', ''), 'sub': user_info['sub']}
     * Store token: request.session['access_token'] = token['access_token']
     * Return RedirectResponse(url='/', status_code=303)  # 303 See Other for POST-redirect-GET pattern
   - Except Exception as e:
     * Log error: logger.error(f"Authentication failed for provider {provider}: {str(e)}")
     * Raise HTTPException(401, f"Authentication failed: {str(e)}")

Why: authorize_access_token() exchanges authorization code for tokens and validates state parameter automatically (see RESEARCH.md "Don't Hand-Roll"). Check email_verified claim before trusting email - not all providers verify emails by default (see RESEARCH.md "Common Pitfalls #3"). Store minimal session data - only what's needed for authorization. Use 303 redirect to prevent browser re-POST on refresh. DO NOT store refresh_token in session - it's sensitive and not needed for this phase (session-based auth). DO NOT skip email_verified check - unverified emails are a security risk.
  </action>
  <verify>Manual test: Complete login flow, verify request.session contains 'user' and 'access_token', verify email_verified=false rejects with 400</verify>
  <done>/auth/callback/{provider} endpoint created, exchanges code for token, validates email_verified, stores session, redirects to /, handles errors with 401</done>
</task>

  <name>Task 3: Create /auth/logout endpoint and user info retrieval endpoint</name>

  <action>
In src/api/routers/auth.py:
1. Implement @router.get("/logout") async def logout(request: Request):
   - Clear session: request.session.clear()
   - Return RedirectResponse(url='/', status_code=303)
2. Implement @router.get("/me") async def get_current_user_info(request: Request):
   - Get user = request.session.get('user')
   - If not user: raise HTTPException(401, "Not authenticated")
   - Return user dict (email, name, sub, provider)

Why: session.clear() removes all session data including tokens - this is a client-side logout only. For true SSO logout, would need to redirect to IdP logout endpoint (deferred to Phase 5 - API Security & Sessions). /me endpoint provides user info for frontend without requiring full JWT validation (session-based auth is sufficient for now). DO NOT implement IdP logout in this phase - it requires provider-specific logout URLs and token revocation (complex, out of scope). DO NOT return access_token in /me response - tokens should stay in backend session only.
