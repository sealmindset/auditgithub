## This Session (2026-08-11, first half) — closing the commit-message vector
`scripts/hunt/hunt_commit_messages.py` was `INCOMPLETE` for one measured reason: GitHub commit search does not index commits that exist only on a non-default branch (proven by its own control — 0 of 5 off-default commits returned, 3 of 3 on-default returned), and this campaign pushes to up to 50 side branches per repository. Two new passes answer that population directly instead of through the index:

- **Free pass**, no requests: `branches_r5.json` already holds `message_first_line` for every in-window commit the branch collector inspected. Matching the marker set against text already on disk read **112 messages, 75 of them on a non-default ref**, with the matcher proven on that text (control token `feat(snip-2048):` matched 3).
- **Range pass**: the branch collector reads the *head* commit of each push, but a push carries a range. Paginated `GET /repos/{o}/{r}/compare/{before}...{after}` read **118 of 141 in-window push events, 786 commits**, with full message text.

**0 marker hits. Vector is now CLEAR.** Two things were not swept under it: three pushes exceeded the compare endpoint's own 250-commit ceiling and were read instead from the ref's history bounded to the campaign window (recorded in the artifact, not silent); and 15 commits plus 23 deletion events sit on refs deleted inside the window (HTTP 422 — the object is gone), which is a coverage gap owned by the repository owners rather than unfinished work.
