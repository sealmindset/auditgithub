unclassified; every actionable finding resolves to a knowledge-base key; no figure appears in a

- **Assuming Alembic governs the live schema.** `security_portal` has **no `alembic_version`
  table**. Schema comes from `models.Base.metadata.create_all()` at `src/api/main.py:243`, which
  creates missing *tables* but never adds *columns*. Column-adding migrations (023, 026, 027)
  silently never reach this database; new-table migrations (024, 025) apply by accident via
  `create_all`. Conclusion: writing a column migration and assuming it landed is a false
  positive. Verify with `information_schema.columns`.

  Everything runs in `auditgh_api` with `--noconftest -p no:cacheprovider`.

  bind-mounted from the working tree. What is *not* pointless: uvicorn has no `--reload`, so a

- **Using `remediation_category NOT IN ('excluded')` to count actionable findings.** Returned
  769,633, which is wrong. Exclusion is a **separate boolean column**,
  `excluded_from_actionable`; `excluded` is not a category value. Correct actionable count is
  222,844.

  post-re-inclusion numbers and published `rotate_secret` 28,568 alongside excluded 547,013.
  Live values are **28,600** and **546,981**, and 222,844 + 546,981 = 769,825 reconciles. Take
  every figure from a query in the same message that publishes it.
- **Assuming `findings.cwe_id` holds CWEs.** It holds exactly two values across all 769,825 rows:
  empty (710,126) and the literal string `HorusecEngine` (59,699). **Zero real CWEs.** This kills
  the CWE -> CAPEC -> ATT&CK chain as originally specified; advisory enrichment recovers CWEs for
  only the 13.4% of actionable findings that carry an advisory.
- **`_MIN_USEFUL_CHARS` as an absolute gate in `markdown_excerpt`.** A document whose first

- **Assuming the empty `remediations` table meant nobody used the feature.** It meant the feature

  `/ai/remediate` filtered on the primary key while every read endpoint publishes `finding_uuid`.
  Generalization: an empty table is a symptom, not a conclusion -- check whether the write path
  can succeed before attributing it to disuse.

  entries would have counted 1,481 model outputs that never happened. That is the exact confusion
  `source` exists to prevent, and it appeared in the column's first use. A row is `ai` only once

## 5. Failed Approaches -- DO NOT RETRY

**From this session (UI work):**

- **`BASELINE_REF = "HEAD"` in a before/after report.** Correct while the work was uncommitted,
  silently wrong the instant it was committed: the "before" column started measuring the fixed
  tree and the appendix collapsed from 134,770 bytes to 17,786. A moving baseline makes the
  before/after table converge on zero difference over time -- **the one failure mode that looks
  like success.** Both report scripts are now pinned to `e8b2899`. Do not un-pin, and do not
  "simplify" the pin to `HEAD` because it reads cleaner.
- **`git ls-files <ref> -- <path>`.** It reads the **index** and ignores the ref argument
  entirely. It reported 5 files at baseline, which is a false negative for the version-control
  finding -- those files did not exist at baseline. Use
  `git ls-tree -r --name-only <ref> -- <path>`, which returns 0 there and 5 at HEAD. Documented
  as a footnote in companion §1.8.
- **Writing a rule into a docstring while an auditor enforces that rule.** Happened twice. The
  `lib/chart.ts` docstring contained a literal `bg-blue-500` and re-triggered `raw-palette-class`;
  the ThreatRadar docstring contained `ctx.fillStyle = "var(--sev-critical)"` and broke a codemod
  assertion (`expected 1, found 2`). Conclusion: any new auditor check needs comment-skipping
  (`COMMENT_LINE_RE`) before the rule can be documented in the code it governs. Prose about an API
  is not a call to it.
- **Two heuristic attempts at the canvas check.** The first caught 2 of 13 broken sites. The

  false-positived on `bgColors[viewMode]`. Conclusion: "did a token reach the canvas" is not

  27 on `0d05aa6`.
