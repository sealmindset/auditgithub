## Overview

This feature allows users to push architecture documentation directly to their GitHub repositories:
- **Git README button:** Replaces repository README.md with the architecture report
- **Git PNG button:** Adds architecture diagram as PNG to repository root

## 🔧 Not Yet Implemented: PNG Conversion

### Issue

The backend `push-diagram` endpoint is created but returns a 501 error because Mermaid → PNG conversion is not implemented.

### Options for Implementation

#### Option 1: Use Mermaid CLI (Server-side)

```bash
# Install mermaid-cli in Docker container
npm install -g @mermaid-js/mermaid-cli

# Convert in Python
subprocess.run([
    "mmdc",
    "-i", mermaid_file_path,
    "-o", output_png_path,
    "-b", "transparent"
])
```

#### Option 2: Use mermaid.ink API

```python
import requests
import base64

def mermaid_to_png(mermaid_code: str) -> bytes:
    # Encode mermaid code
    encoded = base64.urlsafe_b64encode(mermaid_code.encode()).decode()

    # Fetch PNG from mermaid.ink
    url = f"https://mermaid.ink/img/{encoded}"
    response = requests.get(url)

    if response.status_code == 200:
        return response.content
    else:
        raise Exception("Failed to convert Mermaid to PNG")
```

#### Option 3: Use Playwright/Puppeteer (Headless Browser)

Most reliable but requires headless browser in Docker.

### Recommendation

Use **Option 2 (mermaid.ink)** for quick implementation, or **Option 1 (Mermaid CLI)** for offline/secure environments.

## Environment Variables

### Required GitHub Tokens

The system looks for tokens in this order:

1. **Organization-specific token:**
   ```bash
   ORG_EXAMPLE_ORG_LABS_TOKEN=ghp_xxx
   ORG_EXAMPLE_ORG_TOKEN=ghp_yyy

2. **Fallback to default:**

   GITHUB_TOKEN=ghp_zzz
   ```

## Error Handling

### Backend Errors

The API returns appropriate HTTP status codes:
- `404` - Repository not found
- `403` - Repository doesn't belong to specified organization
- `400` - No architecture content available
- `500` - Git operation failed (network, auth, etc.)
- `501` - Feature not implemented (PNG conversion)

### Frontend Fallback

When Git push fails, the frontend should:
1. Show error toast with message
2. **Automatically trigger download** of the file (README.md or PNG)
3. User can manually commit the downloaded file

## Security Considerations

### ✅ Implemented

1. **Organization Verification:** Prevents pushing to repos in wrong org
2. **Token Scoping:** Uses org-specific tokens when available
3. **Repository Ownership:** Validates repo belongs to org before push
4. **Temporary Directory Cleanup:** Removes cloned repos after operation
5. **No User Credentials:** Uses system GitHub tokens, not user tokens

### ⚠️ Considerations

1. **Direct Push to Main:** No PR creation, pushes directly
2. **Token Permissions:** Ensure GitHub tokens have `repo` scope
3. **Overwrite Risk:** README is completely replaced (not merged)
4. **Rate Limiting:** No rate limiting on Git operations yet
