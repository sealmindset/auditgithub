# Phase 10.1: Scan Type Customization

## Objective

Add per-repository scanner selection to the override dialog, allowing users to customize which security tools run for each scheduled scan.

Purpose: Enable fine-grained control over scan coverage per repository based on language, risk profile, or performance needs.
Output: Working scanner selection UI integrated with existing schedule management.

## Tasks

### Task 1: Add new API endpoint for available scanners

Expose the list of available scanners as an API endpoint for the UI to consume.

**Files:** `src/api/routers/schedules.py`

**Action:**
1. Add a new Pydantic model `ScannerInfo` with fields: id (str), name (str), category (str), description (str)
2. Add a constant `AVAILABLE_SCANNERS` list at module level with scanner metadata grouped by category:
   - secrets: trufflehog, whispers
   - sast: semgrep, codeql, horusec, bearer
   - deps: safety, pip-audit, npm-audit, retirejs, govulncheck, bundle-audit, dependency-check, syft, grype
   - iac: checkov, trivy, terrascan, dockle
   - api: api-audit, nuclei
   - mobile: mobsf
   - go: gosec, golangci-lint
   - other: cloc, ossgadget
3. Add GET /schedules/scanners endpoint that returns the list
4. No auth required (scanner list is not sensitive)

**Verification:**
- `curl http://localhost:8000/schedules/scanners` returns JSON array with scanner info
- Response includes all 26 scanners grouped by category

**Commit:** `feat(10-01): add GET /schedules/scanners endpoint`
