# Phase 17 Plan 01: Dashboard Customization

## Objective

Allow users to show/hide dashboard widgets and save their preferences to localStorage for persistence across sessions.

## Execution Context

**Phase dependencies:**
- Phase 11-16: All dashboard widgets created

**Key files to create/modify:**
- `src/web-ui/hooks/useDashboardLayout.ts` - Hook for layout state management
- `src/web-ui/components/dashboard/DashboardCustomizer.tsx` - Settings panel
- `src/web-ui/app/page.tsx` - Integrate customization

**Existing patterns to follow:**
- useWidgetData hook pattern for state management
- Widget component structure

## Context

**Customization scope:**
- Toggle widget visibility (show/hide)
- Persist preferences in localStorage
- Simple settings panel with checkboxes

**Widgets to make configurable:**
- HeroMetrics
- SecurityOverviewWidget
- ScanActivityWidget
- BackgroundJobsWidget
- RepositoryHealthWidget
- FindingTrendsWidget
- QuickActionsWidget
- ThreatRadar
- AIInsightsPanel
- ExecutiveSummaryCards
- SeverityChart
- Recent Critical Findings table

## Tasks

### Task 1: Create useDashboardLayout Hook

Create hook that:
- Manages widget visibility state
- Loads/saves preferences from localStorage
- Provides toggle functions
- Has sensible defaults (all visible)

### Task 2: Create DashboardCustomizer Component

Create settings panel with:
- List of widgets with checkboxes
- "Reset to defaults" button
- Collapsible panel or modal
- Integrates with useDashboardLayout hook

### Task 3: Integrate with Dashboard Page

- Add customizer toggle button to header
- Conditionally render widgets based on visibility
- Wrap widgets with visibility checks

## Verification

- Toggling widgets shows/hides them
- Preferences persist after page refresh
- Reset restores all widgets
