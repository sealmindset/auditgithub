### Task 2: Wire org context to schedule API calls

Ensure schedule API calls respect the selected organization context via tenant middleware.

**Files:** `src/web-ui/app/scheduler/page.tsx`

**Action:**
1. The API already uses `get_tenant_db` middleware which reads org context from request headers/session
2. Verify fetchSchedules includes proper headers for org context
3. Add `credentials: 'include'` to all fetch calls to ensure session cookies are sent
4. The OrganizationSelector already calls `POST /organizations/{name}/select` which sets server-side org context
5. Since OrganizationSelector does a full page reload on org change, the fetchSchedules will automatically use the new org context

**Key insight:** The multi-tenant middleware (`get_tenant_db`) handles filtering automatically once the org is selected on the API side. No query params needed - the session-based org context handles it.

**Verification:**
- Select different org → page reloads → schedules from new org appear
- Verify in Network tab that /schedules calls use `credentials: 'include'`
- Console shows schedule count changes between orgs

**Commit:** `feat(09-01): add credentials to schedule API calls`
