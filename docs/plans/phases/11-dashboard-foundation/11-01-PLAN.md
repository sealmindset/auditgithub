# Plan 11-01: Widget System Foundation

## Objective
Create a reusable widget system foundation with consistent styling, loading states, and error handling that can be used to build the dashboard widgets in subsequent phases.

## Execution Context
- **Phase**: 11 - Dashboard Foundation
- **Milestone**: v2.0 Dashboard Redesign
- **Depends on**: v1.0 complete
- **Estimation**: Small (~45 min) - 3 focused tasks

## Context

### Current State
The existing dashboard at `src/web-ui/app/page.tsx` already has a functional layout with several components:
- HeroMetrics, ThreatRadar, AIInsightsPanel, ExecutiveSummaryCards, SeverityChart
- Uses CSS Grid with `grid gap-6 lg:grid-cols-5` pattern
- Components fetch their own data and handle loading/error states individually
- Components are in `src/web-ui/components/dashboard/`

### What This Plan Creates
1. **Widget wrapper component** - Consistent card styling with header, loading skeleton, error state
2. **DashboardGrid component** - Flexible grid layout that can be customized in Phase 17
3. **Widget hooks** - `useWidgetData` for standardized data fetching with loading/error states

### Design Decisions
- Keep existing dashboard components working (no breaking changes)
- New widget system is opt-in; existing components can be migrated incrementally
- Widget component uses composition pattern (children-based) not configuration
- Grid system uses CSS Grid with named areas for future customization

## Tasks

### Task 1: Create Widget Component
**Goal**: Build the core Widget wrapper component with consistent styling

**Implementation**:
1. Create `src/web-ui/components/dashboard/Widget.tsx`
2. Widget component structure:
   - `Widget` - Outer container with Card styling
   - `WidgetHeader` - Title, subtitle, optional action button, feedback button slot
   - `WidgetContent` - Main content area with padding
   - `WidgetSkeleton` - Loading state placeholder
   - `WidgetError` - Error state with retry button
3. Props interface:
   - `title`: string
   - `subtitle?`: string
   - `action?`: ReactNode (for "View All" type buttons)
   - `loading?`: boolean
   - `error?`: string | null
   - `onRetry?`: () => void
   - `className?`: string
   - `children`: ReactNode
4. Style with existing patterns from HeroMetrics/ExecutiveSummaryCards

**Verification**: Component renders correctly in Storybook-like manual test

### Task 2: Create DashboardGrid Component
**Goal**: Build flexible grid layout component for widget arrangement

**Implementation**:
1. Create `src/web-ui/components/dashboard/DashboardGrid.tsx`
2. Component features:
   - Responsive grid: 1 col mobile, 2 col tablet, 4 col desktop
   - `span` prop on children for colspan (1-4)
   - CSS Grid with gap-6 (matching current)
3. Props interface:
   - `children`: ReactNode
   - `className?`: string
4. GridItem sub-component for span control:
   - `span?`: 1 | 2 | 3 | 4 (default 1)
   - `children`: ReactNode

**Verification**: Grid renders with various span configurations

### Task 3: Create useWidgetData Hook
**Goal**: Standardize data fetching pattern for widgets

**Implementation**:
1. Create `src/web-ui/hooks/useWidgetData.ts`
2. Hook signature:
   ```typescript
   function useWidgetData<T>(
     endpoint: string,
     options?: {
       refreshInterval?: number
       enabled?: boolean
       initialData?: T
     }
   ): {
     data: T | null
     loading: boolean
     error: string | null
     refetch: () => Promise<void>
   }
   ```
3. Features:
   - Auto-refresh with configurable interval (default: none)
   - Respects org query param from URL
   - Handles API errors gracefully
   - Returns refetch function for manual refresh
4. Use existing pattern from ExecutiveSummaryCards as reference

**Verification**: Hook works with a test endpoint
