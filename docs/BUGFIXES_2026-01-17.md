## Bug 1: UnboundLocalError in Auto-Ingestion

### Problem
```python
UnboundLocalError: cannot access local variable 'scan_results' where it is not associated with a value
```

**Location:** [scan_repos.py:6249](scan_repos.py#L6249)

**Error Log:**
```
2026-01-17 04:10:19,618 - ERROR - An error occurred: cannot access local variable 'scan_results' where it is not associated with a value
```

### Root Cause

The `scan_results` variable was only initialized inside the multi-repo code block (line 6081):

```python
if args.repo:
    # Single repository mode
    process_repo(...)  # scan_results NOT initialized
else:
    # Multi repository mode
    scan_results = {...}  # Only initialized here
    ...

# Later, at line 6249:
if not args.dry_run and not args.no_auto_ingest and scan_results['success'] > 0:
    # UnboundLocalError if single-repo mode was used!
```

### Fix Applied

Initialized `scan_results` at the start of main(), before any conditional branching:

**File:** [scan_repos.py:6027-6034](scan_repos.py#L6027-L6034)

```python
# Initialize scan_results at the start to prevent UnboundLocalError
scan_results = {
    'success': 0,
    'timeout': 0,
    'error': 0,
    'skipped': 0,
    'total': 0
}

try:
    session = make_session()

    if args.repo:
        # Single repository mode
        scan_results['total'] = 1
        scan_results['success'] = 1  # Assume success
        ...
    else:
        # Multi repository mode
        scan_results['total'] = len(repos)  # Update total
        ...
```

### Impact
- **Before:** Crashed when auto-ingest tried to check scan_results in single-repo mode
- **After:** scan_results always initialized, auto-ingest works correctly

## Bug 2: Progress Calculation Overflow

### Problem
```
📊 Progress: 853/1 repos (85300.0%)
```

**Location:** [scan_repos.py:2198](scan_repos.py#L2198)

**Error Log:**
```
2026-01-17 04:10:19,304 - INFO - 📊 Progress: 853/1 repos (85300.0%)
```

### Root Cause

Resume state corruption: `completed_repos` had 853 entries but `total_repos` was only 1.

This can happen when:
1. Resume state file persists across different scan runs
2. Previous scan processed 853 repos, current scan is single-repo mode
3. completed_repos list isn't cleared when switching scan modes

**Calculation:**
```python
percentage = (completed / total * 100) if total > 0 else 0
# = (853 / 1 * 100) = 85300.0%  ❌
```

### Fix Applied

Added safety check to cap completed at total:

**File:** [scan_repos.py:2194-2199](scan_repos.py#L2194-L2199)

```python
completed = len(self.completed_repos)
remaining = max(0, self.total_repos - completed)

# Safety check: if completed > total, something is wrong (corrupted state)
# Cap completed at total to prevent absurd percentages
if completed > self.total_repos and self.total_repos > 0:
    logging.warning(f"Resume state corrupted: completed ({completed}) > total ({self.total_repos}). Capping to total.")
    completed = self.total_repos
    remaining = 0

progress = {
    'completed': completed,  # Now capped at total
    'remaining': remaining,
    'total': self.total_repos,
    'percentage': (completed / self.total_repos * 100) if self.total_repos > 0 else 0,
    ...
}
```

### Impact
- **Before:** Displayed absurd percentages like 85300%
- **After:** Caps at 100%, logs warning about corrupted state

## Bug 3: Database Connection Error Handling

### Problem
```
database "org_sleepnumberlabs" does not exist
```

**Location:** Multiple (scan_repos.py, validate_post_deployment.py)

**Error Log:**
```
2026-01-17 04:10:19,302 - ERROR - Error resetting failures for android-pump-finder:
(psycopg2.OperationalError) connection to server at "db" (172.18.0.6), port 5432 failed:
FATAL:  database "org_sleepnumberlabs" does not exist
```

### Root Cause

1. **Multi-tenant database confusion:** Scanner tried to connect to tenant-specific database that doesn't exist
2. **No helpful error message:** Validation script crashed with raw psycopg2 error

### Fix Applied

Enhanced database connection with better error handling:

**File:** [validate_post_deployment.py:35-58](validate_post_deployment.py#L35-L58)

```python
def get_db_connection():
    """Get database connection with error handling."""
    try:
        conn = psycopg2.connect(
            host=DB_HOST,
            port=DB_PORT,
            database=DB_NAME,
            user=DB_USER,
            password=DB_PASS,
            connect_timeout=10
        )
        return conn
    except psycopg2.OperationalError as e:
        print(f"❌ Database connection failed: {e}")
        print(f"\nConnection details:")
        print(f"  Host: {DB_HOST}")
        print(f"  Port: {DB_PORT}")
        print(f"  Database: {DB_NAME}")
        print(f"  User: {DB_USER}")
        print(f"\nPossible causes:")
        print(f"  1. Database container not running (docker ps | grep auditgh_db)")
        print(f"  2. Wrong database name (check DB_NAME env var)")
        print(f"  3. Network issues between containers")
        raise
```

### Impact
- **Before:** Cryptic psycopg2 errors, hard to debug
- **After:** Clear error message with troubleshooting steps

## Lessons Learned

### 1. Initialize Variables Early
**Problem:** Variable initialized inside conditional block
**Solution:** Initialize at function start, update in conditionals
**Prevention:** Static analysis, code review checklist

### 2. Validate Intermediate State
**Problem:** Resume state can become corrupted
**Solution:** Add safety checks for impossible conditions
**Prevention:** State validation tests, sanity checks

### 3. User-Friendly Error Messages
**Problem:** Raw psycopg2 errors hard to debug
**Solution:** Wrap with context and troubleshooting steps
**Prevention:** Error handling guidelines, UX review
