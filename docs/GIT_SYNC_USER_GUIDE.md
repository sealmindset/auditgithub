# Git Sync Feature - User Guide

**Quick Reference:** How to push architecture documentation to GitHub repositories

---

## Overview

The Git Sync feature allows you to automatically push your architecture documentation directly to your GitHub repositories:

- **Git README** - Replaces your repository's README.md with the architecture report
- **Git PNG** - Adds the architecture diagram as a PNG image to your repository root

## How to Use

### Step 1: Generate Architecture Documentation

Before using Git Sync, you need architecture documentation:

1. Navigate to your repository's project page
2. Click on the **Architecture** tab
3. Click **"Generate Architecture"** button
4. Wait for AI to analyze and generate:
   - Architecture Report (text)
   - Python Diagram Code
   - Rendered Diagram Image

### Step 2: Push README to GitHub

Once you have an architecture report:

1. Click the **Report** tab
2. Review the generated report content
3. Click **"Git README"** button (top-right of the card)
4. Wait for confirmation toast

**What Happens:**
```
1. System clones your repository
2. Replaces README.md with architecture report
3. Commits: "Update README with architecture report [automated]"
4. Pushes to your default branch (main/master)
5. Shows success message
```

**On Success:**
```
✓ Success: README.md updated successfully
```

**On Error:**
```
✗ Error: Failed to push README. Use download fallback.

↓ README.md automatically downloads
→ You can manually commit the file
```

### Step 3: Push Diagram PNG to GitHub (Optional)

Once you have an architecture diagram:

1. Stay on the **Diagram** tab (default)
2. Verify diagram image is visible
3. Click **"Git PNG"** button (above tabs)
4. Wait for operation to complete

**Current Behavior:**
```
⚠ PNG conversion not yet implemented

↓ {repository-name}.png automatically downloads
→ You can manually commit the file to repository root
```

**Future Behavior** (when PNG conversion is implemented):
```
1. System converts diagram to PNG
2. Clones your repository
3. Adds {repository-name}.png to root directory
4. Commits: "Add architecture diagram [automated]"
5. Pushes to your default branch
6. Shows success message
```

## Understanding the Process

### What "Git README" Does

**Step-by-Step:**

1. **Validates:** Checks repository belongs to your selected organization
2. **Gets Token:** Uses GitHub token configured for your organization
3. **Clones:** `git clone https://github.com/{org}/{repo}.git`
4. **Replaces:** Overwrites README.md with architecture report
5. **Stages:** `git add README.md`
6. **Commits:** `git commit -m "Update README with architecture report [automated]"`
7. **Pushes:** `git push origin HEAD`
8. **Cleans Up:** Removes temporary clone directory

**Commit Details:**
- **Author:** AuditGH Bot <noreply@auditgh.local>
- **Message:** "Update README with architecture report [automated]"
- **Branch:** Your default branch (usually `main` or `master`)

### What "Git PNG" Will Do (When Implemented)

1. **Converts:** Mermaid diagram code → PNG image
2. **Validates:** Checks repository belongs to your organization
3. **Gets Token:** Uses GitHub token for your organization
4. **Clones:** `git clone https://github.com/{org}/{repo}.git`
5. **Adds:** Saves `{repo-name}.png` to repository root
6. **Stages:** `git add {repo-name}.png`
7. **Commits:** `git commit -m "Add architecture diagram [automated]"`
8. **Pushes:** `git push origin HEAD`
9. **Cleans Up:** Removes temporary clone directory

## Important Considerations

### README Replacement

⚠️ **Warning:** The "Git README" button **completely replaces** your existing README.md file.

**Before clicking:**
- Ensure you don't need content from your current README
- Architecture report is comprehensive and can serve as your main README
- You have a backup if needed (Git history preserves old README)

**Why replace instead of append?**
- Architecture report is designed to be a complete, standalone documentation
- Prevents README from becoming cluttered with duplicated sections
- Maintains clean, professional documentation structure

**Can I undo?**
- Yes! Use `git revert` to restore previous README
- GitHub preserves full history of all changes

### Direct Push to Main

⚠️ **Note:** Git Sync pushes **directly to your default branch** without creating a pull request.

**Implications:**
- No code review process for these commits
- Changes appear immediately in your repository
- Bypasses branch protection rules (if bot account has admin access)

**Why direct push?**
- Automated documentation updates typically don't require review
- Faster workflow for keeping docs in sync
- Reduces PR noise for routine documentation updates

**Future Enhancement:**
- Option to create pull request instead of direct push
- User can choose workflow that fits their team's process

### Organization Verification

✅ **Security:** The system verifies repositories belong to your selected organization.

**What this means:**
- You cannot accidentally push to repositories in other organizations
- Each organization uses its own GitHub token
- Prevents cross-organization security issues

**Error message:**
```
Repository belongs to {ActualOrg}, not {SelectedOrg}
```

**Solution:**
- Ensure correct organization is selected in the UI
- Check repository actually belongs to selected organization

## Troubleshooting

### Button Doesn't Appear

**Problem:** "Git README" or "Git PNG" button not visible

**Check:**
1. Has architecture been generated? Click "Generate Architecture"
2. Is organization data loaded? Check project has organization assigned
3. Are you in edit mode? Click "Cancel" to exit edit mode
4. Does repository have architecture content in database?

**Fix:**
- Generate architecture if not present
- Refresh page if organization data not loaded
- Exit edit mode
- Check Architecture tab shows content

### Push Fails

**Problem:** Error toast: "Failed to push README"

**Common Causes:**

1. **GitHub Token Missing/Invalid**
   ```
   Error: GitHub token not configured for organization: {org}
   ```
   **Fix:** Configure `ORG_{ORG}_TOKEN` or `GITHUB_TOKEN` in `.env`

2. **No Write Permissions**
   ```
   Error: Git push failed: Permission denied
   ```
   **Fix:** Ensure GitHub token has `repo` scope permissions

3. **Repository Not Found**
   ```
   Error: Repository not found
   ```
   **Fix:** Verify repository exists and token has access

4. **Network Error**
   ```
   Error: Git operation timed out
   ```
   **Fix:** Check network connection, retry operation

**Fallback:**
- System automatically downloads the file
- You can manually commit and push the downloaded file

### Wrong Organization

**Problem:** Error: "Repository belongs to {X}, not {Y}"

**Cause:** Repository is in a different organization than selected

**Fix:**
1. Check which organization owns the repository
2. Select correct organization in UI
3. Retry Git Sync operation

### PNG Download Instead of Push

**Problem:** PNG downloads instead of pushing to repository

**Cause:** PNG conversion not yet implemented (expected behavior)

**Status:** This is the current intended behavior

**Workaround:**
1. Download completes automatically
2. Manually commit `{repo-name}.png` to repository root
3. Push to GitHub

**Future:** PNG will push automatically once conversion is implemented

## Best Practices

### 1. Review Before Pushing

Always review the generated report before clicking "Git README":
- Check for accuracy
- Verify sensitive information not exposed
- Ensure quality meets your standards

### 2. Use Version History

If you need to track changes:
1. Click "History" button (in Architecture tab header)
2. Save version before pushing to GitHub
3. Add description: "Pre-GitHub push v1"
4. Can restore previous versions if needed

### 3. Coordinate with Team

Before replacing README:
- Inform team members
- Check if anyone is working on README
- Ensure no merge conflicts will occur

### 4. Test in Non-Production First

First time using Git Sync:
- Test on a non-critical repository
- Verify behavior meets expectations
- Review commit in GitHub before rolling out to important repos

### 5. Maintain Backup

Although Git preserves history:
- Keep copy of original README (just in case)
- Document what sections were replaced
- Note any custom content that was removed

## FAQ

**Q: Can I edit the report before pushing?**

A: Yes! Click "Edit" button, modify the report, click "Save Changes", then click "Git README".

**Q: Does this create a pull request?**

A: No, it pushes directly to your default branch. PR creation is a planned future enhancement.

**Q: What if my README has important content?**

A: Git preserves history. Use `git revert` to restore previous README. Better: ensure architecture report is comprehensive enough to serve as complete README.

**Q: Can I push to a different branch?**

A: Not yet. Currently pushes to default branch only. Branch selection is a planned enhancement.

**Q: Does it work with GitHub Enterprise?**

A: Yes, as long as your GitHub token and repository URL are configured correctly.

**Q: Can I customize the commit message?**

A: Not yet. Currently uses: "Update README with architecture report [automated]". Customization is a planned enhancement.

**Q: What happens if the push fails?**

A: System shows error message and automatically downloads the file for manual commit.

**Q: Can I push to multiple repositories at once?**

A: Not yet. Batch operations is a planned future enhancement.

**Q: Will this trigger CI/CD pipelines?**

A: Yes, if your repository has push-triggered workflows. The commit will trigger them like any other push.

**Q: Can I schedule automatic updates?**

A: Not yet, but this is a great idea for future enhancement!
