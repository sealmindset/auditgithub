## Critical Findings

### CRIT-001: Next.js Remote Code Execution (CVE-2025-55182)

- **Severity:** CRITICAL
- **What happened:** The Next.js version used in `src/web-ui` is vulnerable to pre-authentication remote code execution via the React Server Components flight protocol. An attacker can execute arbitrary code on the server without authentication.
- **Where it occurred:** `src/web-ui/package-lock.json` -- next package
- **How the failure occurred:** npm audit detected CVE-2025-55182 (range: >=16.0.0-canary.0 <16.0.7)
- **Root cause analysis:** The Next.js dependency has not been updated to the patched version (16.0.7+).
- **Risk matrix entry:**
  - Likelihood: Likely (4) -- public exploit, no auth required
  - Impact: Severe (5) -- full server compromise
  - Risk Level: **CRITICAL (20)**
- **Compensating controls:**
  - Upgrade Next.js to >=16.0.7 immediately
  - WAF rules to filter malicious flight protocol payloads
  - Network-level isolation of the frontend container
- **Remediation type:** PROGRAMMATIC_FIX
- **Evidence:** npm audit output, CVE-2025-55182

### CRIT-002: jsPDF Local File Inclusion / Path Traversal (CVE-2025-68428)

- **Severity:** CRITICAL
- **What happened:** The jsPDF library has a path traversal vulnerability that allows reading arbitrary files from the server filesystem when generating PDFs.
- **Where it occurred:** `src/web-ui/package-lock.json` -- jspdf <=3.0.4
- **How the failure occurred:** npm audit detected CVE-2025-68428
- **Root cause analysis:** jsPDF does not sanitize file paths when processing image or font resources.
- **Risk matrix entry:**
  - Likelihood: Possible (3) -- requires PDF generation feature access
  - Impact: Significant (4) -- arbitrary file read (config, secrets)
  - Risk Level: **CRITICAL (12)**
- **Compensating controls:**
  - Upgrade jsPDF to patched version when available
  - Restrict PDF generation to authenticated users only
  - Sandbox PDF generation in an isolated container
- **Remediation type:** PROGRAMMATIC_FIX

### CRIT-003: jsPDF Cross-Site Scripting (CVE-2026-31938)

- **Severity:** CRITICAL
- **What happened:** jsPDF contains a cross-site scripting vulnerability via unsanitized output options.
- **Where it occurred:** `src/web-ui/package-lock.json` -- jspdf <=3.0.4
- **Root cause analysis:** Output options are not properly sanitized, allowing script injection.
- **Risk matrix entry:**
  - Likelihood: Possible (3) -- requires user interaction with PDF
  - Impact: Significant (4) -- session hijacking, data theft
  - Risk Level: **CRITICAL (12)**
- **Remediation type:** PROGRAMMATIC_FIX

### CRIT-004: Execution Agents Bypass All AI Safety Controls

- **Severity:** CRITICAL
- **What happened:** Four AI agent files in `execution/` make direct Anthropic API calls with unsanitized inputs, no output validation, no PII masking, and no safety preamble. The `ai_credential_matcher.py` explicitly sends full credential values to the external LLM.
- **Where it occurred:**
  - `execution/ai_credential_matcher.py` (lines 390, 417, 1728)
  - `execution/ai_credential_url_agent.py`
  - `execution/ai_api_discovery.py` (line 240)
  - `execution/ai_org_agent.py`
- **How the failure occurred:** Code-level audit confirmed zero imports from `services.ai_safety` in any execution/ agent file.
- **Root cause analysis:** The AI safety module was retrofitted into the chat service pipeline but not into the pre-existing execution agents, which were written before the safety module existed.
- **Risk matrix entry:**
  - Likelihood: Almost Certain (5) -- these code paths are actively used
  - Impact: Significant (4) -- credential leakage to external AI provider, prompt injection
  - Risk Level: **CRITICAL (20)**
- **Compensating controls:**
  - Integrate `sanitize_prompt_input()` into all execution/ agent LLM calls
  - Integrate `mask_pii()` before sending credential data to external LLM
  - Add `validate_agent_output()` after all LLM responses
  - Route execution/ agents through `llm_provider.py` base class (which has preamble)
- **Remediation type:** PROGRAMMATIC_FIX

### CRIT-005: src/ai_agent/ Subsystem Has Zero Safety Integration

- **Severity:** CRITICAL
- **What happened:** The entire `src/ai_agent/` subsystem (11+ files, multiple LLM provider implementations) has no integration with the AI safety module. No prompt sanitization, no output validation, no PII masking, no error sanitization, no safety preamble.
- **Where it occurred:** `src/ai_agent/` directory (agent.py, providers/*.py, reasoning.py, remediation.py, diagnostics.py, learning.py, contributor_analyzer.py, ops_discovery_agent.py)
- **Root cause analysis:** Same as CRIT-004 -- safety module was added to chat service but not to the agent framework.
- **Risk matrix entry:**
  - Likelihood: Almost Certain (5) -- active code paths
  - Impact: Significant (4) -- prompt injection, data leakage
  - Risk Level: **CRITICAL (20)**
- **Remediation type:** PROGRAMMATIC_FIX

## High Findings

### HIGH-001: SQL Injection via sqlalchemy.text() (9 locations)

- **Severity:** HIGH
- **What happened:** Multiple scripts and modules use `sqlalchemy.text()` with string-formatted SQL, which passes user-controlled values directly into SQL statements.
- **Where it occurred:**
  - `migrations/tenant_runner.py:64,103`
  - `scripts/backup_organization.py:134`
  - `scripts/maintenance/cleanup_ghost_repos.py:91,130`
  - `scripts/maintenance/ingest_reports.py:250`
  - `scripts/maintenance/validate_scan_metadata.py:93`
  - `scripts/migrate_secret_validation.py:41,48`
- **Root cause analysis:** `sqlalchemy.text()` accepts raw SQL strings. When combined with f-strings or `.format()`, user input flows directly into the query.
- **Risk matrix entry:**
  - Likelihood: Possible (3) -- scripts require authenticated access
  - Impact: Significant (4) -- data exfiltration, modification
  - Risk Level: **HIGH (12)**
- **Compensating controls:**
  - Use parameterized queries: `text("SELECT * FROM t WHERE id = :id").bindparams(id=value)`
  - Add input validation before query construction
- **Remediation type:** PROGRAMMATIC_FIX
